Problem & Motivation

High Volatility

Gold prices are highly sensitive to geopolitical and macroeconomic factors.

Legacy Models

Traditional linear models fail to capture complex, non-linear market behaviors.

Data Cost

Real-time financial datasets from major providers are prohibitively expensive.

Proposed Solution

Free Data Streams

Harvesting PAXG token prices from Binance Public API at zero cost.

Advanced ML

Utilizing LightGBM via ML.NET for highly accurate, non-linear regression.

Microservices

Decoupled REST API deployment automated entirely via Docker & CI/CD.

System Architecture

A decoupled, 3-layer enterprise architecture.

Data Harvesting Layer

Automated Scraper

  • Connects directly to Binance Klines API.
  • Fetches 1,000 Daily Candlesticks in a single request.

OHLCV Format

Features: Open, High, Low, Volume

3rd-Party API Integration

Powering the Real-time Prediction Engine

Binance Spot API

Fetches the current second's OHLCV values to serve as live input for model inference.

Exchange Rate API

Converts USD predictions to VND natively. Includes a robust Fallback Mechanism if the API fails.

Machine Learning Layer

  • ML.NET v3.0: Microsoft's native AI framework. Seamless integration with C#.
  • LightGBM: A highly efficient Gradient Boosting framework.
Why LightGBM?

GOSS: Filters out noise efficiently.

Leaf-wise: Splits trees at the highest-error nodes for faster convergence.

API Serving Layer

ASP.NET Core 10

Built with Minimal API architecture for maximum throughput and zero boilerplate code.

PredictionEnginePool

Security & Rate Limiting

Fixed Window Rate Limiter

Limit: 5 Requests / 10 Seconds

Protects the application from DDoS attacks and abusive scraping.
Prevents the exhaustion of free 3rd-Party API quotas.

Web Frontend UI

  • Glassmorphism: Premium, modern financial design language.
  • Zero-Click Experience: JS automatically fetches and displays real-time predictions upon page load.
  • Served natively via ASP.NET static files middleware.
Instant Results

Sub-500ms latency from initial page load to prediction display.

Docker Multi-Stage Build

Stage 1: Build (~800MB)

Uses heavy .NET SDK image to restore packages and compile source code to binaries.

Stage 2: Runtime (~200MB)

Uses lean ASP.NET Runtime. Contains only the final .dll and ML model file.

Result: 70% reduction in production image size.
